## 原因

1. **变量少不等于 GLPK 当前形式的工作量小。** 6阶的五组多项式共35个变量，但全部障碍交点一次性作为约29万行送入通用单纯形。稀疏矩阵、辅助变量、预处理和基更新的成本依赖这些行。当前每个点通常产生多个横截面交点，约束数远大于点数。
2. **初始可行性阶段负担重。** `glp_init_smcp` 后未指定算法，使用默认原始单纯形；全部35列自由变量、约束全部是正下界，零系数起点违反全部行。限时日志直接显示可行性阶段进展慢。相邻点/截面对应高度相关行，可能增加退化与数值困难；没有在线基统计，不能把具体迭代次数归因于某一种退化机制。
3. **没有工作集/约束生成。** 即使绝大部分点横向离参考很远，也全部装入当前 LP。97% 的交点超过3m，但不能据此直接删除：当前 wrapper 是离散角度/参数采样约束，不能当作连续半径上界证明。
4. **数值缩放与精度缺少配合。** 行里同时有 w1²、w2²、2w1w2、w1、w2 和 Chebyshev 基，横向距离达到43m；代码没有显式 glp_scale_prob 或自定义行归一化，却把 tol_bnd/tol_dj 设到1e-8。存在尺度差和高相关行风险，但未计算条件数，不能据此断言唯一数值失败原因。之前的 return=5 和残差失败说明需要同时检查稳定性。
5. **全局多项式将全路径耦合。** 208个参考段没有产生208个独立小 LP；所有障碍约束共同约束同一35维全局系数。简单逐段解椭圆会改变问题及连续性，不能当作等价加速。
6. **同步回调放大等待体验。** plan 在单线程 ros::spin 的目标回调内完成，生产 solver 没有时间/迭代预算，且关闭日志；长求解期间同一回调队列的 reset/新目标无法及时处理。只有成功后才保存指标，失败请求缺少阶段记录。RViz 和落盘位于求解之后，不是当前持续占核的原因。

## 小规模方向验证：显式对偶

仅在独立诊断程序中把同一个 LP `min cᵀx, Ax≥b, x自由` 写成 `max bᵀy, Aᵀy=c, y≥0`，35行、289607列；保留全量约束，关闭对偶模型预处理，仍用默认 simplex，设置3秒预算。注意“显式对偶模型”不等同于给原模型设置 GLP_DUAL 算法。

单次结果：3164.05ms、262次迭代，165次迭代时已经找到对偶可行解；返回code=9、status=2（可行但未达到最优）。**没有得到已验证走廊，不能声称3秒求解完成或给出加速倍数。** 这说明重新组织 LP 值得实测，但还需恢复原问题系数、检查对偶间隙、原始全部残差及连续正定性。

## 建议处理顺序

1. 给真实生产流程补充分阶段指标、LP规模、迭代数、返回码和失败记录；明确预算与可取消后台任务。先解决不可观测的无限等待。
2. 优先测试约束生成：从可行的受限子问题开始，在全体286779个交点上检查违反量，批量加入违反约束，保留必要正定/wrapper约束并热启动；直到完整约束复核通过才接受。不能以仅检查抽样点替代全量检查。保留全局多项式定义。
3. 同输入比较显式对偶、原始/对偶单纯形以及行缩放；统一目标值、残差、连续正定和时间口径。缩放后的求解器容差必须换算回原始约束复核，不能靠放松安全检查换取速度。
4. 投影可缓存系数或做保守候选筛选，但当前仅0.64秒，不是首先优化的环节。GPU地图渲染、A*邻域或线程数也不是这次主要方向。
5. 不直接换 real_planner 的 Seidel SDLP：35维不是其常见的1/4维使用情形；仓库此前820约束测试在35维已超过30秒，不能预期29万约束直接替换即可加速。

## 原始材料与复现

`results/performance_dense/` 保存本次 cloud.xyz、astar.xyz、replay.cpp、generator_instrumented.cpp、generator_dual.cpp、replay.log、replay_dual.log。diagnostic源文件只加日志/时间限制或显式对偶试验，没有替换正在运行的库。

容器内在该目录执行：

```bash
g++ -O3 -DNDEBUG -std=c++17 -I../../include -I/usr/include/eigen3 \
  replay.cpp generator_instrumented.cpp -L/root/ws/corr_gen/devel/lib \
  -Wl,-rpath,/root/ws/corr_gen/devel/lib -lcorrgen -lglpk -o replay
nice -n 10 ./replay
# 对偶试验将 generator_instrumented.cpp 换为 generator_dual.cpp
```

GLPK 提供原始/对偶单纯形，参见 [GNU GLPK](https://www.gnu.org/software/glpk/)。运行库为 Docker GLPK4.65；生产配置 samples101、wrapper_angles24、wrapper_radius3、positive_margin0.02、exclusion_margin1e-5、feasibility_tolerance1e-6。
