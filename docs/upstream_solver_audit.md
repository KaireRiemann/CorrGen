# 官方实现与当前慢速 LP 的差异审计

> 历史分析/试验记录；当前实现、默认后端与验收数据以 [工程交付报告](engineering_delivery.md) 为准。

2026-10-27。核对论文全文 https://arxiv.org/html/2407.12283v1 和作者仓库 commit `5a0f48a0e02b4f0051df652e33ce21926171b701`。本次仅分析和统计，未修改生产节点。

## 官方具体做法

- `examples/kitti.py:150-154` / `examples/toy_example.py:96-100`：SDP 用 Clarabel；LP 用 `cp.PROXQP, backend="dense"`。GUROBI、OSQP 是注释掉的替代选项，不是运行的默认后端。没有用SDLP或GLPK。
- `requirements.txt`：cvxpy1.4.2，Linux proxsuite0.6.3。ProxQP 本身是C++实现，具有Python绑定，可直接接入C++；LP可以作为H=0的QP交给它，不必添加改变目标的二次惩罚。需以官方版本和统一残差复核建立基准。
- `corrgen/corrgen.py:126-151`：对离散参考与点云做最近点投影，每点仅保留一次；prune模式仅保留绝对切向残差小于0.01的点。
- `examples/kitti.py:95-119`：去除z<=-1.5的地面，加入cage，最近点投影及切向剪枝，最后保留横向距离<=20/1.5的点。
- `corrgen/corrgen.py:36-121`：N=100，5组degree+1系数；每个最终occupancy只添加一条障碍约束，并非每点乘100；LP分支仅添加每个采样的a>=c、b>=c共200条约束。
- 论文III-C明确提出wrapper及移除wrapper外点；IV Numerical implementation明确说明LP用ProxQP、SDP用Clarabel。
- 没有发现本仓库示例实现了切平面/约束生成或SDLP递归算法。工作集方案是针对当前全量约束提出的改进，不应归给作者。

## 当前实现为什么慢

1. 全地图104508点，208段曲线，枚举全部横截面实根，产生286779条障碍约束；再加2828条wrapper/严格对角占优约束。35变量但矩阵非零项近991万。
2. 当前没有wrapper范围裁剪及工作集，97%的障碍约束横向距离超过3m；glpk单纯形的可行性阶段已经显示进展缓慢。很多远点可能不影响最优边界，但没有先验严格证明就不能直接删除。
3. 35维Seidel SDLP有明显维度代价。相同dense点云，5维约148ms通过，35维60秒超时，说明不是单一的约束个数问题，而是维度、求解算法与约束结构共同作用。
4. 数据尺度跨度、近似相关约束、较严格容差可能增加数值困难。此前残差失败和GLPK失败不能仅归咎于硬件或语言。
5. 全量投影重放约640ms，LP装配约150ms，主体瓶颈在求解；但即使求解降到很快，当前投影仍阻止直接达到50ms全流程目标。
6. 严格四侧对角占优相较官方仅增加约200行；这不足以解释从3000到29万行。连续正定认证的时间也不能作为当前单纯形长期停留的解释。
7. 当前同步ROS回调没有取消预算、阶段计时不足，使长时间求解表现为界面一直等待。这是执行控制缺陷，不是数学模型必须如此。

## 不能直接复制的裁剪

官方a>=c,b>=c并不对负c保证正定；应保留当前四侧正定约束。KITTI的去地面规则来自驾驶场景，不能直接用于三维飞行地图。离散参考最近点投影和1cm切向剪枝会删除离散投影误差较大的点，不能自动视为当前多转弯路径的完整碰撞检查。离散wrapper采样也不提供连续域的严格半径上界。

当前方法更保守地保留全部交点，是一种模型差异；但扩大问题后没有匹配算法和规模控制，是当前实现应解决的问题，不能以更保守为由接受数分钟延迟。

## 推荐的处理路线

1. **先建立官方后端基线。** 接入ProxQP C++，保持H=0、相同全局系数/目标/安全约束。对官方原始规模先复现，再对保存的sparse/dense全量LP进行限时对照。记录装配/投影/solver/校验、返回状态、原始残差、目标与最优性间隙。不能承诺换后端必然实时。
2. **增加受限工作集和约束生成。** 按u、横截面方向和距离挑选初始候选，保留正定及wrapper；解后在所有原始交点上检查，加入违反约束并热启动，直到全量满足。原问题有限集合保留；初始化的距离筛选只是候选，不是永久删点。若子问题最优且解对全问题可行，则其目标也是全问题最优；实际数值计算还要检查最优性容差与残差。不要人为把工作集上限锁死为35条：退化、数值条件与非顶点解会影响这一简化。
3. **如需永久裁剪，先建立可认证的走廊包络。** 在整个参数区间证明包含关系后才移除包络外的障碍点；仅取离散wrapper不能完成此证明。纯体素下采样也不能替代障碍占据体积约束。
4. **主体LP解决后，再处理投影640ms。** 缓存段多项式系数、保守空间/参数候选筛选、并行处理独立点，保留所有可能相交的截面；不通过随意降低采样率掩盖问题。
5. **异步执行与明确预算。** 把计算移出ROS输入回调，可取消超期请求，失败保存数据。预算耗尽必须报超时而非无路，不发布未验证走廊。

全程保持当前全局可微参数化；第一轮不需要退回常数截面或独立分段椭圆。按固定原始数据先做单因素比较：同一完整LP换求解器、再加工作集、最后优化投影。这样能区分加速究竟来自哪里。

论文报告约5~20Hz，但示例打印的prob._solve_time不包含先前的路径准备、投影、手工构建CVXPY表达式等全部阶段，不能与当前ROS端到端时间直接等同。官方毫秒数也不应被当作当前50m地图的无条件性能承诺。
