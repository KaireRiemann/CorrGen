# 可微参数走廊的工程化方案与算法选择

2026-10-27。本文保留实施前的设计分析；新后端、工作集、进程预算及体素包围检查现已实现，当前状态和未完成研究项见 [engineering_delivery.md](engineering_delivery.md)。下文的“当前/建议”保留原设计时态。不会把目标时延写成已达成结果；轨迹优化不在当前范围。

## 1. 推荐主线

短期保留6阶全局Chebyshev和全路径输入，采用“解析可行初值 → 小工作集优化 → 全量分离检查 → 已认证结果保底”的迭代流程。ProxQP C++作为与论文一致的首选实验后端，HiGHS作为独立LP校核及候选主后端。以同输入、同目标、同约束的实验选型，不根据库名承诺速度。

改进分三类：

- 不改变有限LP：坐标/行缩放且正确反变换、约束生成、批量装配、准确去重、热启动、求解器切换。
- 改变表示或可行域：B-spline系数参数化、强制包络、机器人膨胀、连续正定条件、偏好正则项。必须单独比较质量与安全，不能称为相同LP加速。
- 仅改运行机制：异步执行、取消、快照版本、缓存、状态诊断。改善稳定响应，但不降低数学问题复杂度。

## 2. 当前模型可以解析生成可行初值

对于所有有效横截面交点w_i，令r_min=min ||w_i||，wrapper半径R，正定裕量epsilon，障碍裕量delta。若r_min>0且有限，可选

alpha > max(epsilon, (1+delta)/r_min^2, (1+delta)/R^2)

令a(u)=b(u)=alpha、c(u)=d(u)=e(u)=0，则q=alpha||w||²−1。它在任意degree>=0的现有参数空间中可表示：只有常数项非零。

这满足当前全部有限障碍/wrapper约束和整个区间严格对角占优；实现仍需考虑舍入裕量并执行现有全部检查。若交点集合为空，则忽略对应r_min项；若有w=0，则当前q(0)=-1与障碍约束矛盾，不能生成这个初值。距离太小会导致alpha很大，应报告几何净空/尺度问题。

这不是“0阶求解器替代6阶”：它是6阶模型中的一个可行初值，高阶系数随后可以变化。该推导也意味着，对于有限且非零的交点、没有新增上界约束的当前模型，不能轻易把求解器数值失败称为数学不可行。

限制：构造前必须获得可靠r_min，若由当前全投影得到仍花费约640ms；没有凭空绕过几何开销。这个窄管可能极细且没有机器人净空，只能称点云模型可行，不能称可飞。GLPK不能仅写入一个x向量就自动获得有效基；需按后端的warm-start/basis接口正确使用。

## 3. 优化不应阻塞第一个可用结果

定义两个独立结果维度：
- 验证范围：POINT_MODEL_VALID / VOXEL_BODY_VALID。
- 优化程度：FEASIBLE / OPTIMAL_WITHIN_TOLERANCE / BUDGET_EXHAUSTED。

先保存一个通过全部所需验证的incumbent，再优化trace目标。超时可返回同一请求、同一地图快照下已认证的incumbent，明确其优化程度；没有认证结果就报告失败。不能发布部分约束满足的解，也不能复用另一路径/旧地图的走廊。

trace下降是原代理目标改善，不保证真实体积或最小净空单调增加。日志记录目标、最小净空、截面范围及最优性间隙，避免“更优目标”被误读为每个截面都扩大。

## 4. 工作集与分离检查器

全部约束作为轻量几何数据保存，例如u、w、来源point/segment ID；只对当前工作集生成系数行。初始工作集保留正定/wrapper，并在参数区间和横向方向上选近障碍、上一请求经过重新匹配验证的候选。

循环：
1. 求解受限问题，检查返回码与原始单位残差。
2. 扫描全部原始交点，检查q>=delta；按u/方向分桶选违反严重的点，批量加入，避免所有新增行集中在一个位置。
3. 无违反点且连续正定/域/碰撞检查通过，才更新可接受结果。
4. 有违反则继续；达到时间、内存、迭代预算时返回已认证结果或明确超时。

受限最小化问题最优值是完整有限问题最优值下界；若受限最优解对全问题也可行，则已达到完整最优。实际中需验证对偶可行性和原始单位的间隙，不能把近似求解器的目标值直接当严格下界。删除不活跃行可能引发循环，第一版先采用只增不删；后续才加冷却/重新检查机制。

完整验证不要求每次持有29万×35矩阵。缓存Chebyshev值或使用低分配开销的q值专用函数，避免调用当前会计算gradient/Hessian的evaluate。扫描约M×D而不是在巨大LP结构中反复迭代。此复杂度分析不等于实测速度保证；工作集最坏仍可能增长到全部约束。

连续正定检查若发现不满足的u，可添加对应a±c/b±c约束并重求；达到认证分割预算但无法确定时应报告UNVERIFIED，而非把采样通过当作证明。

## 5. 求解器选型

| 方案 | 建议角色 | 局限 |
|---|---|---|
| ProxQP C++ | 首先建立论文一致基线；小工作集、热启动 | H=0的退化LP、精度与全量规模仍需实测 |
| HiGHS | 独立LP最优值/残差基准；工作集增量求解候选 | simplex/IPM不同配置表现需比较；不能承诺默认就快 |
| SDLP | 5维常数截面或真正极低维子问题 | 当前35维已超时，不作为全局主后端 |
| OSQP | 将来确实加入平滑/时间一致性QP目标时再比较 | 原始LP高精度收敛不能靠默认容差假设；本阶段不优先扩展 |
| 显式对偶 | 同一LP形式对照 | 改变矩阵方向不减少非零项；此前仅找到对偶可行解，不等于得到原始最优走廊 |
| 自研专用内点法 | 后续研究选项 | n小m大可形成n阶系统，但装配O(MD²)，仍有正则、尺度及失败证书工作；不适合作为第一轮工程修复 |

ProxQP、HiGHS均有C++接口；ProxQP提供warm-start及不同dense线性代数后端。初始化、行数改变后的工作区更新、目标/残差口径都应进入对比。算法内部proximal正则与人为在目标增加lambda||x||²不同，后者会改变优化问题。

## 6. 几何层：从点云demo到机器人可用

现在参考线检查的是占据体素，但走廊排除的只是点中心，而且inflation默认0、wrapper不严格限制地图边界。因此必须统一几何语义。

建议将已知占据体素实体按机器人包围球半径加定位/建图误差裕量做配置空间膨胀，再将走廊解释为机器人中心允许区域。未知区域、地图边界、地面和顶面策略必须明确。不能把q的1e-5无量纲裕量当成米制净空。

A*、参考圆滑化、走廊验收必须共享同一膨胀地图快照。走廊检验需覆盖整个扫掠体与占据体素的不相交，可用有保守界的区间细分/包围体广相检查；无法界定的区域继续细分或拒绝认证。仅检查参考线、椭圆离散采样或体素八顶点都不足以证明扫掠体安全。此认证层是独立工程工作，不能声称当前已有。

裁剪远点前应先证明全走廊包含于某包络，再用包络与体素空间索引筛选。没有包络证明时，可用于候选排序，但最终检查不能遗漏被删区域。包络边界约束与偏心椭圆的连续包含关系必须按实际参数化推导，不能假设加圆周点就等价。

## 7. 参考路径与参数化

先保留现有全局6阶模型，控制变量以建立优化基线。当前50m路径被按0.5m及其细分构造成许多段；后续可依据转弯、障碍净空自适应确定几何控制点，通过碰撞/偏差检查合并冗余段，保留全程及精确端点。更少段有助于全横截面投影，但不能按固定预算删掉必须的转弯。

若全局模型在长路径上体积或局部适应性不足，再改五组系数为低阶B-spline。三次简单内节点的系数函数C2，单个参数值仅少量基函数非零；局部修改不影响整条路径。变量数可能增加、矩阵更稀疏，不保证必然更快。正定可通过控制系数四侧占优充分条件保证，但更保守；需要与区间认证方案比较。

局部q的C2不自动等于世界管道C2。目前参考线C2但标架只保证C1。若后续优化依赖世界坐标二阶导数，应使参考线/标架具有相应更高正则性，检查切向非退化与坐标映射局部可逆，并处理自交/多投影分支。不能仅替换系数基函数后宣布满足世界C2。

## 8. 软件结构和执行模型

建议渐进拆分，不引入与任务无关框架：

```
map/       MapSnapshot、膨胀占据、空间索引、版本
geometry/  A*、参考、标架、投影候选
corridor/  参数化、轻量ConstraintSet、工作集、连续检查
solver/    统一问题数据、ProxQP/HiGHS/SDLP适配
validation/点模型与体素/机体/边界验证报告
ros/       选点、请求调度、状态、可视化
apps/      固定输入重放与后端对比
```

让各solver读取统一问题数据，删除“先造GLPK对象再转SDLP矩阵”的试验式依赖；前期仍可保留GLPK离线基准。

ROS回调只接收输入并提交带request_id/map_version/config_hash的请求。地图作为不可变快照，worker只读取快照。latest-request-wins：新目标/地图变更取消旧任务，并在原子发布前再次核对版本。简单AsyncSpinner无法自动解决并发写状态和旧结果覆盖问题。

支持协作取消的阶段定期检查token；不可中断的solver放在可终止的独立worker进程。不要超时后仅detach线程，让后台计算永久占核。首次实现可先单worker，避免多个大LP争抢CPU/内存。

状态明确区分：等待选点、搜索中、投影中、优化中、验证中、可行已验证、最优容差内、超时、取消、地图过期、无路径、数值失败、验证未完成。旧走廊若展示，只能明确标为历史结果，不能发布为当前有效走廊。

## 9. 验收与性能目标

两级验收：
- 交互工程版：有限点云模型验证范围明确，响应不卡死，全程路径完整、可重放、超时/取消可靠。
- 机器人可用版：额外通过膨胀实体地图、边界、全走廊扫掠体验证；无轨迹优化不等于已经可以直接控制飞行。

建议首阶段目标（需确认硬件后实测，并非当前结果）：输入状态更新<100ms；固定50m地图合法请求集首个已验证点模型走廊p95<=1s；单次规划预算3s，取消生效目标<=200ms。若现有投影640ms尚未改善，不承诺50ms端到端。库调用预算不是严格硬实时墙钟保证，进程调度也必须纳入实际统计。

固定保存的地图、端点、真实cloud、配置和库版本测试，不能仅用随机种子假设完全复现；上游多面体有独立random_device。覆盖稀疏/中/密、短长路径、正反向、多高度、U形/多转弯、窄缝、越界、无路、重复选点、地图中途更新。记录p50/p95/p99、成功/超时/数值失败比例，峰值内存，候选/完整约束数、工作集轮数及最大违反量。随机排列多次重复，最终速度测试单worker且关闭无关并发负载。

每次无论成功失败，都保存分阶段计时、输入hash、后端、约束规模、返回码、容差、最优性间隙及验证范围。不要以仅成功样本平均耗时作为性能结论。离线高精度基准检查目标/约束，工程版优先保证可行与预算，再衡量质量损失。

## 10. 实施顺序

A. 统一模型接口和失败日志，ProxQP/HiGHS同数据离线基准；建立可行初值验证。
B. 工作集+全量检查+可行结果保底，修复默认35维求解速度。
C. 同一膨胀地图的几何验证与边界认证；投影与参考段优化。
D. 可取消worker、快照版本与原子发布；RViz明确显示有效性和超时。
E. 固定回归集验收。只有全局模型表达力/稀疏性成为实测限制时，再研究B-spline参数化，不同时替换全部模块使性能归因失效。

阶段C和D可在B后按当前最突出问题调整顺序，但实体安全认证是机器人可用版的必要门槛。论文复现和工程扩展分别维护配置、结果与差异说明。
